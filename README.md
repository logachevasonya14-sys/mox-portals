# Лаборатория нестабильных порталов

Инструмент смотрителя лаборатории нестабильных порталов: список порталов, расчёт риска, действия с ограничениями, журнал событий, сводка и AI Worklog внутри приложения.

- **Приложение:** https://logachevasonya14-sys.github.io/mox-portals/
- **Репозиторий:** https://github.com/logachevasonya14-sys/mox-portals

## Сценарий за 1 минуту

1. Вверху — сводка (нажми «Развернуть», чтобы увидеть порталы категории) и **ряд порталов-дверей**: цвет — уровень риска, критические пульсируют, внутри — число риска. Ниже — таблица, справа — карточка выбранного портала.
2. Кликни **Врата Никты** (критический риск 90, внутри 3 существа).
3. Нажми **«Отправить наблюдателя»** → действие заблокировано (риск ≥ 80), причина показана рядом с кнопками и записана в журнал.
4. Нажми **«Стабилизировать»** → риск падает 90 → 68 (критический → высокий).
5. Нажми **«Закрыть портал»** → предупреждение, что внутри существа. Нажми **«Отмена»**.
6. **«Отправить наблюдателя»** → теперь разрешено, наблюдатель эвакуирует существ.
7. **«Закрыть портал»** → подтверждение «действие необратимо», уже без предупреждения о существах. **«Да, закрыть навсегда»** — портал закрыт, любое действие с ним блокируется.
8. Вкладка **«Журнал событий»** — все операции, включая заблокированные, с датой и временем.
9. Блок **«Демо-данные»**: **«Очистить список»** — пустое состояние, **«Сбросить демо»** — вернуть исходные данные (оба с подтверждением).
10. На телефоне: порталы видны на одном экране, таблица — карточками, карточка портала открывается отдельным экраном со строкой «← К порталам».

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Тесты и production-сборка:

```bash
npm test
npm run build
npm run preview
```

Бэкенда, авторизации и секретов нет. Состояние хранится в `localStorage` браузера.

## Стек и структура

React 19 + TypeScript + Vite, тесты — Vitest.

```
src/
  logic.ts                  ПРАВИЛА: типы, формула риска, что можно/нельзя,
                            хранение в localStorage, русские подписи, демо-данные
  logic.test.ts             тесты логики
  App.tsx                   состояние (порталы, журнал, что выбрано) + обработчики + вкладки
  components/
    PortalsTab.tsx          сводка, ряд порталов-дверей, таблица
    PortalCard.tsx          карточка выбранного портала: цифры, рекомендация, кнопки, история
    EventLogTab.tsx         журнал событий
    WorklogTab.tsx          вкладка AI Worklog
    ui.tsx                  общие мелочи: значок риска, плашка сообщения, форматирование
  worklog.ts                текст вкладки AI Worklog
  main.tsx                  запуск + экран ошибки (ErrorBoundary)
  styles.css                оформление
```

Правило: **logic.ts решает, компоненты показывают.** В logic.ts нет ничего про экран — только чистые функции «данные на вход → результат на выход», поэтому правила проверяются тестами без браузера. App.tsx хранит состояние и обработчики, а компоненты получают данные через props и сообщают о нажатиях через колбэки — сами они ничего не меняют.

## Формула риска

```
risk = round(energy × 0.35) + round((100 − stability) × 0.45) + round(urgency × 0.20)      (0–100)
```

| Время до схлопывания | ≤15 мин | ≤30 | ≤60 | ≤120 | ≤240 | больше |
|---|---|---|---|---|---|---|
| urgency | 100 | 85 | 65 | 40 | 20 | 5 |

Каждое слагаемое округляется отдельно, поэтому разбивка в карточке всегда точно складывается в итог. Пороги уровней заданы константами в `src/logic.ts`.

Уровни: **0–29 низкий**, **30–59 средний**, **60–79 высокий**, **80–100 критический**. У закрытого портала операционный риск 0.

Почему так: нестабильность — главный фактор (45%), потому что именно она приводит к схлопыванию; энергия усиливает последствия (35%); срочность (20%) поднимает приоритет тех, что вот-вот схлопнутся. Разбивка по слагаемым видна в карточке портала («Почему N/100?»).

## Действия и ограничения

| Действие | Эффект | Когда запрещено |
|---|---|---|
| Стабилизировать | стабильность +25, энергия −10, +30 мин до схлопывания | портал закрыт; стабильность уже ≥ 90 |
| Отправить наблюдателя | эвакуирует существ, снимает флаг «под вопросом» | портал закрыт; риск ≥ 80 (критический) |
| Пометить «под вопросом» / снять пометку | переключает пометку: ставит или снимает (на случай, если нажали по ошибке) | портал закрыт |
| Закрыть портал | статус → closed, энергия и таймер → 0 | уже закрыт. **Всегда требует подтверждения** (действие необратимо); если внутри существа — дополнительно предупреждает о них |

Заблокированные кнопки помечены 🔒, но остаются кликабельными: попытка показывает причину рядом с кнопками и пишется в журнал с пометкой «заблокировано».

## Тесты

`npm test` — 23 unit-теста (Vitest):

- формула совпадает с документацией, разбивка всегда складывается в итог, границы уровней риска (79 → наблюдатель разрешён, 80 → запрещён);
- критический портал определяется как critical;
- стабилизация снижает риск;
- закрытый портал: риск 0, все действия заблокированы;
- наблюдатель не отправляется в критический портал;
- закрытие всегда требует подтверждения, а с существами внутри предупреждение называет их;
- полный сценарий critical → stabilize → observer → безопасное закрытие;
- нельзя стабилизировать стабильный портал; пометку «под вопросом» можно свободно поставить и снять;
- битый / чужой JSON в `localStorage` отбрасывается, а не роняет приложение;
- демо-данные покрывают обязательные состояния;
- русские формы множественного числа («1 существо / 3 существа / 5 существ»).
